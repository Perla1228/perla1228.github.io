一、实验设置与统计口径

先把指标和范围讲清楚，结论才可信。

  • 数据与题目：自建中文电商库（8 表、800 订单、2024-06 ~ 2025-08），50 题分 easy / medium / hard，覆盖单表、2 表 JOIN、3 表 JOIN + HAVING + 子查询。
  • 指标：Valid SQL（能否执行）、严格 EX（结果行列完全一致）、答案等价 EX（本报告主指标）。
  • 答案等价 EX 定义：行数一致，且 gold 的每一列都能在模型结果里找到；允许模型多返回辅助列（如顺带带上销量/销售额），允许 ID 与名称等价（1 与「数码电子」视为同一个值），忽略列顺序。
  • 口径复核：逐题对照业务语义，修正了 19 条题目本身的逻辑错误（过滤条件写在 JOIN ON 里失效、ORDER BY 用明细列、缺聚合/GROUP BY、分母口径错、明细重复累加等），明细见 reports/gold_sql_review.xlsx。
  • 缺失处理：接口超时/限流产生的空输出按「缺失」处理，不计入分母（表中「有效题数」已扣除），避免把调用失败算成模型能力问题。
  • 消融实验：仅取 glm-4.5-flash 与 deepseek-flash，各跑「简单提示 / 加强提示」两档，共 4 组 × 50 题；qwen-plus 只参与横向对比。
为什么消融没有 qwen-plus？ 消融需要成对运行（模型 × 2 档提示），加千问意味着多 2 组全量调用；其响应延迟高、成本不合算，且它在横向对比中 hard 题并不占优，不改变「加强提示为负收益」的方向。因此消融结论仅代表 glm 与 deepseek 两个模型，不外推到 qwen-plus。

四、典型案例

每个模型各取 1 条正确、1 条失败，对比 gold_sql 与模型生成 SQL。

正确 智谱 glm-4.5-flash Q36 · hard
各年龄段用户销售额怎么样
gold_sql
select case
  when u.age between 18 and 25 then '18-25岁'
  when u.age between 26 and 35 then '26-35岁'
  when u.age between 36 and 45 then '36-45岁'
  when u.age between 46 and 60 then '46-60岁'
  else '60岁以上'
end as age_bucket, sum(o.total_amount) as total_sales
from orders o left join users u on o.user_id = u.user_id
where o.status = '已完成'
group by age_bucket
order by age_bucket
模型生成 SQL
SELECT 
    CASE 
        WHEN age BETWEEN 18 AND 25 THEN '18-25岁'
        WHEN age BETWEEN 26 AND 35 THEN '26-35岁'
        WHEN age BETWEEN 36 AND 45 THEN '36-45岁'
        WHEN age BETWEEN 46 AND 60 THEN '46-60岁'
        WHEN age >= 61 THEN '60岁以上'
        ELSE '未知年龄段'
    END AS age_group,
    SUM(orders.total_amount) AS sales_amount
FROM 
    users
JOIN 
    orders ON users.user_id = orders.user_id
WHERE 
    orders.status = '已完成'
GROUP BY 
    age_group
ORDER BY 
    age_group;

失败 DeepSeek flash Q23 · medium
不同渠道下单用户分布情况
gold_sql
select c.channel_name, count(distinct o.user_id) from orders o left join channels c on o.channel_id = c.channel_id group by c.channel_name
模型生成 SQL
SELECT c.channel_name,
       COUNT(DISTINCT o.user_id) AS user_count,
       ROUND(COUNT(DISTINCT o.user_id) * 100.0 /
             (SELECT COUNT(DISTINCT user_id) FROM orders WHERE status = '已完成'), 2) AS user_pct
FROM orders o
JOIN channels c ON o.channel_id = c.channel_id
WHERE o.status = '已完成'
GROUP BY c.channel_id, c.channel_name
ORDER BY user_count DESC;
归因标签：多列（辅助列 / 口径等价，严格 EX 误判）

六、结论与局限

  • 瓶颈在语义口径，不在语法。 Valid SQL 在 94%~100%，答案等价 EX 只有 77%~88%，失败集中在返回列数、聚合口径、过滤条件。
  • 评测口径本身是最大的误差源。 严格 EX 会低估模型 31 个百分点；评测集 gold 还有 19 条逻辑错误。做 Text2SQL 评测，先把 gold 和口径打磨干净，比换模型更重要。
  • 提示词不是越长越好。 两模型 × 两档提示的消融显示加强提示无正收益，hard 题尤其明显。
  • 局限：hard 仅 15 题，1 题 = 6.7 pt，波动大；消融只覆盖 2 个模型。glm-4.5-flash 有 9 题因接口超时缺失（其中 hard 题占 7 题），其总分与分难度只代表已取得的 41 题，横向可比性弱于另两个模型；缺失按缺失处理，不当作模型错误。
